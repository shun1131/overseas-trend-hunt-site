なぜ流行っているか

ファイルアップロード時の画像処理をローカルで完結でき、プライバシーとスピードで注目されている。フォーム送信前の簡単な画像加工が必要なユースケースが多い。

中核機能

  • ブラウザ上での画像リサイズ・圧縮
  • フォーム統合対応
  • ローカル処理でプライバシー保護
  • 複数形式対応

収益モデル

SaaS/API経由の有料プラン (推定：月額従量制)

個人での攻め筋（本人＋Claude）

SaaS化して API 経由で月額制・従量制のプランを提供。初期ターゲットは「Webデザイナー・ブロガー・eコマース運営者」など画像処理が頻繁な層を集中攻撃。LinkedIn や ProductHunt、設計系コミュニティで告知。同類競合が多いため、「特定業界向けカスタマイズ版」(例：物産EC向け・SNS画像投稿特化) を作り差別化する。

構築難易度 — 2/5

ImageMagick や sharp など既存ライブラリ + React/Vue でブラウザネイティブAPIを組み合わせれば構築可能。WebAssemblyの活用で高速化も本人+Claudeで実装可能。

想定技術スタック

React/Next.jssharp または ImageMagickWebAssembly (Rust/WASM)AWS Lambda/Vercel Functions

片手間運用性 — 4/5

コアは自動実行。利用者がアップロードするだけで完結し、サーバーサイド運用も軽量。SEO や利用シーン発掘に手間がかかる程度。

収益到達性（月20万） — 3/5

月額 3,000〜5,000円で複数のデザイナーや小規模ショップが顧客になりやすい。ただし競合(TinyPNG等)が多く、月20万到達には 50〜70ユーザー必要で、認知・差別化の手間がある。
