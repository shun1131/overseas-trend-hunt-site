なぜ流行っているか

オープン重量モデル (PaddleOCR) の精度向上と GPU 利用コストの低下で、個人が商用 OCR プロバイダーになるハードルが急低下している

中核機能

  • PaddleOCR-VL による高精度文書解析
  • 1,000 ページ月 $1 の超低価格
  • スケーラブルな API エンドポイント

収益モデル

従量課金 (ページ / ドキュメント単位)、ボリュームディスカウント、API キー制御による B2B プラン

個人での攻め筋（本人＋Claude）

Claude が FastAPI で OCR API を構築、GCP / AWS の Spot GPU で超低コスト運用。初期: 個人開発者向けに月 5,000 円のスタータープラン。スケール: B2B (RPA / 文書処理企業) に月 2~5 万。GPU コスト月 3,000 円程度なので粗利率は 80%超

構築難易度 — 2/5

Claude が GPU インスタンス (AWS / GCP) 上に PaddleOCR をデプロイし、Web API でラップするだけ。セットアップスクリプトで自動化可

想定技術スタック

Python (FastAPI / Flask)PaddleOCR-VL モデルAWS / GCP の GPU インスタンスDocker コンテナ

片手間運用性 — 4/5

API は一度起動すれば自動実行。GPU コスト監視とスケーリングが主な運用タスク。自動スケーリング設定で放置可能

収益到達性（月20万） — 4/5

OCR の需要は持続的で、低コスト・高精度の組み合わせは競合少ない。既存 Azure / Google OCR より圧倒的に安く、市場開拓容易
