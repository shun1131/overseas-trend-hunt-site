なぜ流行っているか

データアート・データビジュアライゼーション分野で、複雑な編集流を美しく可視化する作品として強い話題性。継続更新される永続的な美しさ。

中核機能

  • リアルタイムWikipedia編集ストリーム可視化
  • 言語別・ボット別の色分け
  • アーカイブ機能

収益モデル

寄付 / スポンサーシップ / Patreon推定

個人での攻め筋（本人＋Claude）

無料サービスで月500万～1,000万PVを狙い、Patreonで月$500～1,000、スポンサーシップで月$2,000～3,000確保。教育機関・図書館向けにカスタマイズ有料版$99/月も検討。GitHub Sponsorsで月$300～500。合計月$2,500～4,500を目指す。

構築難易度 — 3/5

Wikimedia API経由での編集ストリーム取得、3Dビジュアライゼーション（Three.js等）による摩天楼レンダリング。バックエンド～フロントエンド通じて実装は中度。

想定技術スタック

Node.js BackendWikimedia APIThree.js / WebGLReact / CanvasPostgreSQL

片手間運用性 — 5/5

自動更新がメイン。UIの微調整・新言語追加、バグ対応のみ。ほぼ放置で動作。

収益到達性（月20万） — 3/5

主収入は寄付・スポンサーで、月20万達成には大規模ファンベース必須。Patreon月500～800人×$2～5で月$1,500～4,000程度。企業スポンサーで補完。実現性は中程度。
